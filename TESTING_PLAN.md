# Investment API Swagger UI Testing Plan

Use this plan in Swagger UI to verify authentication, authorization, CRUD operations, and error handling.

## Test environment

- Local API URL: `http://localhost:3000`
- Local Swagger UI: `http://localhost:3000/api-docs`
- Render API URL: replace with your Render URL after deployment
- Render Swagger UI: replace with `https://your-render-service.onrender.com/api-docs`

## Seeded credentials

| Role | Email | Password | Purpose |
| --- | --- | --- | --- |
| Admin | `stkadmin@email.com` | `Admin123!` | Can create, update, and delete assets |
| Regular user | `stkuser@email.com` | `User123!` | Can manage only their own portfolio entries and alerts |

## Seeded data assumptions

After running `npm run seed`, the database includes:

| Resource | Expected seeded examples |
| --- | --- |
| Users | Admin user and regular user |
| Assets | `AAPL`, `TSLA`, `BTC`, `ETH` |
| Portfolio | Regular user owns entries for `AAPL` and `BTC`; admin owns an entry for `TSLA` |
| Alerts | Regular user owns alerts for `AAPL` and `BTC`; admin owns an alert for `TSLA` |

IDs are generated by PostgreSQL. Before testing ID-specific endpoints, use the relevant `GET` list endpoint in Swagger UI and copy real IDs from the response.

## Swagger authorization setup

1. Open Swagger UI at `/api-docs`.
2. Run `POST /api/auth/login` with one of the seeded accounts.
3. Copy the returned `token` value.
4. Click the Swagger `Authorize` button.
5. Paste the token in the bearer auth field.
6. Click `Authorize`.

Do not include the word `Bearer` unless Swagger UI explicitly requires it. The OpenAPI security scheme is configured as HTTP bearer auth, so Swagger normally adds `Bearer` automatically.

## 1. Authentication endpoints

### POST `/api/auth/signup`

Access control: Public.

Success case:

1. Click `POST /api/auth/signup`.
2. Click `Try it out`.
3. Use a unique email:

```json
{
  "email": "newuser1@email.com",
  "password": "User123!"
}
```

4. Click `Execute`.
5. Expect `201 Created`.
6. Response should include `user.id`, `user.email`, `user.role` equal to `user`, and a JWT `token`.

400 Bad Request:

1. Use an invalid email:

```json
{
  "email": "not-an-email",
  "password": "User123!"
}
```

2. Click `Execute`.
3. Expect `400 Bad Request`.

409 Conflict:

1. Use the same signup email twice:

```json
{
  "email": "duplicate@email.com",
  "password": "User123!"
}
```

2. First request should return `201 Created`.
3. Second request should return `409 Conflict`.

### POST `/api/auth/login`

Access control: Public.

Success case:

1. Click `POST /api/auth/login`.
2. Click `Try it out`.
3. Use seeded regular user credentials:

```json
{
  "email": "stkuser@email.com",
  "password": "User123!"
}
```

4. Click `Execute`.
5. Expect `200 OK`.
6. Response should include user details and a JWT `token`.

401 Unauthorized:

1. Use the right email with the wrong password:

```json
{
  "email": "stkuser@email.com",
  "password": "WrongPassword123!"
}
```

2. Click `Execute`.
3. Expect `401 Unauthorized`.

400 Bad Request:

1. Remove the password:

```json
{
  "email": "stkuser@email.com"
}
```

2. Click `Execute`.
3. Expect `400 Bad Request`.

## 2. Assets resource

Assets are the first main resource. The API supports full CRUD.

### GET `/api/assets`

Access control: Any authenticated user.

Setup:

1. Log in as regular user `stkuser@email.com` / `User123!`.
2. Authorize Swagger with the returned JWT.

Success case:

1. Click `GET /api/assets`.
2. Click `Try it out`.
3. Click `Execute`.
4. Expect `200 OK`.
5. Response should include seeded assets such as `AAPL`, `TSLA`, `BTC`, and `ETH`.

401 Unauthorized:

1. Clear the Swagger authorization token.
2. Click `GET /api/assets`.
3. Click `Execute`.
4. Expect `401 Unauthorized`.

### POST `/api/assets`

Access control: Admin only.

Setup:

1. Log in as admin `stkadmin@email.com` / `Admin123!`.
2. Authorize Swagger with the returned JWT.

Success case:

1. Click `POST /api/assets`.
2. Click `Try it out`.
3. Use:

```json
{
  "symbol": "NVDA",
  "name": "NVIDIA Corporation",
  "type": "stock",
  "price": 875.25
}
```

4. Click `Execute`.
5. Expect `201 Created`.
6. Response should include the new asset with symbol `NVDA`.
7. Copy the returned `id` for update/delete tests.

400 Bad Request:

1. Remove required field `symbol`:

```json
{
  "name": "Bad Asset",
  "type": "stock",
  "price": 10
}
```

2. Click `Execute`.
3. Expect `400 Bad Request`.

401 Unauthorized:

1. Clear the Swagger authorization token.
2. Execute the same valid request.
3. Expect `401 Unauthorized`.

403 Forbidden:

1. Log in as regular user `stkuser@email.com` / `User123!`.
2. Authorize Swagger with that JWT.
3. Execute the same valid request.
4. Expect `403 Forbidden`.

409 Conflict:

1. Log in as admin and authorize Swagger.
2. Try to create an asset using an existing symbol:

```json
{
  "symbol": "AAPL",
  "name": "Duplicate Apple",
  "type": "stock",
  "price": 100
}
```

3. Click `Execute`.
4. Expect `409 Conflict`.

### GET `/api/assets/{id}`

Access control: Any authenticated user.

Success case:

1. Log in as regular user and authorize Swagger.
2. Run `GET /api/assets` and copy a real asset `id`.
3. Click `GET /api/assets/{id}`.
4. Enter the copied asset ID.
5. Click `Execute`.
6. Expect `200 OK`.

400 Bad Request:

1. Enter `-10` as the ID.
2. Click `Execute`.
3. Expect `400 Bad Request`.

401 Unauthorized:

1. Clear the Swagger authorization token.
2. Use a valid asset ID.
3. Click `Execute`.
4. Expect `401 Unauthorized`.

404 Not Found:

1. Authorize Swagger with any valid JWT.
2. Enter `999999` as the ID.
3. Click `Execute`.
4. Expect `404 Not Found`.

### PUT `/api/assets/{id}`

Access control: Admin only.

Success case:

1. Log in as admin and authorize Swagger.
2. Create an asset with `POST /api/assets` if you do not already have a test asset.
3. Copy the test asset ID.
4. Click `PUT /api/assets/{id}`.
5. Enter the copied ID.
6. Use:

```json
{
  "price": 899.99
}
```

7. Click `Execute`.
8. Expect `200 OK`.
9. Response should show updated `price`.

400 Bad Request:

1. Enter `-10` as the ID or use a negative price:

```json
{
  "price": -1
}
```

2. Click `Execute`.
3. Expect `400 Bad Request`.

401 Unauthorized:

1. Clear the Swagger authorization token.
2. Use a valid asset ID and valid body.
3. Click `Execute`.
4. Expect `401 Unauthorized`.

403 Forbidden:

1. Log in as regular user and authorize Swagger.
2. Use a valid asset ID and valid body.
3. Click `Execute`.
4. Expect `403 Forbidden`.

404 Not Found:

1. Log in as admin and authorize Swagger.
2. Enter `999999` as the ID.
3. Use valid body:

```json
{
  "price": 899.99
}
```

4. Click `Execute`.
5. Expect `404 Not Found`.

409 Conflict:

1. Log in as admin and authorize Swagger.
2. Create a test asset with symbol `DUP1`.
3. Create another test asset with symbol `DUP2`.
4. Update the `DUP2` asset and set its symbol to `DUP1`:

```json
{
  "symbol": "DUP1"
}
```

5. Click `Execute`.
6. Expect `409 Conflict`.

400 Bad Request:

1. Enter `-10` as the ID.
2. Click `Execute`.
3. Expect `400 Bad Request`.

401 Unauthorized:

1. Clear the Swagger authorization token.
2. Use a valid asset ID.
3. Click `Execute`.
4. Expect `401 Unauthorized`.

403 Forbidden:

1. Log in as regular user and authorize Swagger.
2. Use a valid asset ID.
3. Click `Execute`.

404 Not Found:
